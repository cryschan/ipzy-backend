# Claude.md 파일이란? Claude Code를 위한 5가지 베스트 프랙티스

> 출처: https://apidog.com/blog/claude-md/

---

## 소개

30년 이상의 경험을 가진 C++ 개발자가 60,000줄 리팩토링에서 찾기 어려운 버그를 4년 동안 추적했습니다. 수많은 시간의 조사 끝에 Claude Opus가 약 30개의 프롬프트로 몇 시간 만에 해결했습니다. 이 이야기는 에이전틱 코딩의 힘을 보여줍니다 - 개발자가 프로젝트 컨텍스트, 아키텍처, 히스토리를 이해하는 AI 에이전트와 협업하는 것.

---

## claude.md 파일이란?

### AI 코더를 위한 제어판

`claude.md` 파일은 Claude Code가 프로젝트별 컨텍스트를 얻기 위해 자동으로 읽는 특별한 마크다운 문서입니다. "모든 요청과 함께 따라다니는 사전 브리핑 또는 강한 의견이 담긴 프롬프트"라고 생각하세요. 이 파일은 AI의 일반화된 프로그래밍 지식과 특정 프로젝트의 명문화되지 않은 규칙 사이의 격차를 메웁니다.

### 무엇을 포함해야 하나요?

잘 구조화된 `claude.md`는 다음을 포함해야 합니다:

- **기술 스택**: 프로젝트 도구와 버전 (예: Next.js 14, TypeScript 5.2, Tailwind CSS 3.4)
- **프로젝트 구조**: 주요 디렉토리와 그 목적 (예: `src/components`, `src/lib`)
- **명령어**: 필수 빌드, 테스트, 린트, 배포 스크립트
- **코드 스타일 및 관례**: 명시적인 포매팅 가이드라인과 네이밍 컨벤션
- **저장소 에티켓**: 브랜치 네이밍 패턴, 커밋 형식, merge/rebase 선호도
- **핵심 파일 및 유틸리티**: AI가 알아야 할 필수 파일에 대한 포인터
- **건드리지 말 것 목록**: AI가 수정을 피해야 할 것들

### claude.md는 어디에 위치하나요?

Claude Code는 여러 위치에서 지침을 지능적으로 찾아 계층화합니다:

1. **홈 디렉토리** (`~/.claude/CLAUDE.md`): 모든 세션에 대한 전역 선호도
2. **프로젝트 루트** (`your-repo/CLAUDE.md`): 팀 전체 관례 (버전 관리됨)
3. **하위 디렉토리** (`your-repo/feature/CLAUDE.md`): 세분화된 기능별 컨텍스트
4. **로컬 오버라이드** (`CLAUDE.local.md`): 개인 선호도 (`.gitignore`에 추가)

## 효과적인 claude.md를 만드는 5가지 베스트 프랙티스

### 1. 간결하고 의도적으로: 토큰 예산 존중

황금률: "주니어 개발자를 온보딩하는 게 아니라 Claude를 위해 작성하세요." `claude.md` 내용은 모든 상호작용에서 토큰을 소비하므로 짧고 집중되게 유지하세요.

**해야 할 것:**
- 짧고 선언적인 불릿 포인트 사용
- 중복 제거

**하지 말아야 할 것:**
- 긴 서술형 문단 작성
- 있으면 좋은 주석 포함

### 2. /init으로 시작하고 반복

프로젝트에서 처음 `claude`를 실행할 때 `/init` 명령이 보일러플레이트 `claude.md` 내용을 생성합니다. 살아있는 문서로 취급하세요. 반복적으로 구축하세요:

1. 새 지침 추가
2. Claude에게 그것에 의존하는 작업 부여
3. 관찰하고 개선
4. 반복

세션 중 `#` 키를 사용하면 Claude가 자동으로 지침을 `claude.md`에 통합합니다.

### 3. 명확한 구조

마크다운 제목을 사용하여 논리적으로 구성하세요. 일반적인 구조:

```markdown
# 기술 스택
- 프레임워크: Next.js 14
- 언어: TypeScript 5.2

# 프로젝트 구조
- `src/app`: 페이지
- `src/components`: 재사용 가능한 컴포넌트
- `src/lib`: 핵심 유틸리티

# 명령어
- `npm run dev`: 개발 서버
- `npm run build`: 프로덕션 빌드
- `npm run test`: 유닛 테스트

# 코드 스타일
- ES 모듈 사용
- Hooks가 있는 함수형 컴포넌트
- 화살표 함수 정의

# 금지 섹션
- `src/legacy` 파일 편집 금지
- `main`에 직접 커밋 금지
```

### 4. 환경과 용어 정의

프로젝트의 고유한 환경을 명확히 하세요. 예:

- 가상 환경 설정 지정: "이 프로젝트는 Python 3.11과 함께 pyenv를 사용합니다"
- 프로젝트별 용어 정의: "'Module'은 `src/modules`의 데이터 처리 파이프라인을 의미합니다"

### 5. claude.md를 버전 관리에 포함

메인 `claude.md`를 Git에 커밋하여 팀 전체의 단일 진실 소스를 만드세요. 새 개발자가 합류하면 그들과 Claude 어시스턴트가 즉시 관례에 맞춰집니다. 개인 선호도는 `CLAUDE.local.md`를 사용하세요.

## 고급 팁과 워크플로우 통합

### Opus로 계획, Sonnet으로 실행

다른 모델은 다른 강점이 있습니다:
- **Claude Opus**: 추론, 계획, 복잡한 문제 해결에 탁월
- **Claude Sonnet**: 실행 중심 작업과 빠른 구현에 우수

강력한 워크플로우는 전략적 계획에 Opus를 사용한 다음, 구현을 위해 Sonnet으로 전환합니다 (Claude Code에서 종종 `Shift + Tab`). `claude.md`는 두 모델이 동일한 제약 하에서 작동하도록 보장합니다.

### 사용량 추적

`ccusage` 명령으로 토큰 소비를 모니터링하세요. Anthropic은 Claude를 워크플로우에 많이 통합하는 개발자에게 훨씬 더 많은 사용량을 제공하는 구독을 제공합니다.

## 결론

`claude.md` 파일은 "AI 어시스턴트를 위한 헌법이며, 일반 도구에서 전문화된 프로젝트 인식 개발자로 승격시키는 문서입니다." 간결하고 명확하며 포괄적인 `claude.md`를 만드는 것은 개발 속도, 코드 일관성, 복잡한 도전을 해결할 준비가 된 맞춤형 AI 전문가에 대한 접근성에서 배당금을 지불하는 투자입니다.
