## 원칙: LLM은 (대부분) 상태가 없다

LLM은 상태가 없는 시스템으로 동작합니다 - 추론 중에 가중치가 고정되어 시간이 지나도 학습하지 않습니다. 에이전트는 토큰을 통해 제공하는 것만 알고 있습니다. Claude Code 같은 코딩 하네스는 명시적인 메모리 관리가 필요하며, `CLAUDE.md`는 기본적으로 모든 대화에 나타납니다.

**세 가지 핵심 시사점:**

1. 에이전트는 각 세션을 코드베이스에 대한 지식 없이 시작합니다
2. 중요한 정보는 매 세션마다 전달되어야 합니다
3. `CLAUDE.md`가 선호되는 커뮤니케이션 메커니즘입니다

---

## CLAUDE.md는 Claude를 코드베이스에 온보딩합니다

`CLAUDE.md`는 세 가지 차원을 다뤄야 합니다:

- **WHAT (무엇):** 기술 스택, 프로젝트 구조, 코드베이스 지도. 모노레포에서 특히 중요 - 앱, 공유 패키지, 그 목적을 명확히
- **WHY (왜):** 프로젝트 목적과 각 컴포넌트의 기능
- **HOW (어떻게):** 워크플로우 지침, 도구 선호도 (bun vs node), 검증 방법, 테스트, 타입체크, 컴파일 절차

*중요한 경고:* 가능한 모든 명령어를 이 파일에 넣으려 하지 마세요 - 결과가 나빠집니다.

---

## Claude는 종종 CLAUDE.md를 무시합니다

Claude Code는 파일과 함께 시스템 리마인더를 주입합니다:

> "중요: 이 컨텍스트는 작업과 관련이 있을 수도 없을 수도 있습니다. 작업과 매우 관련이 있는 경우에만 이 컨텍스트에 응답해야 합니다."

따라서 Claude는 보편적으로 적용되지 않는 내용을 무시합니다. 관련 없는 지침은 전반적인 성능을 저하시킵니다.

---

## 좋은 CLAUDE.md 파일 만들기

### 지침은 적을수록 좋다

연구에 따르면 프론티어 LLM은 약 150-200개의 지침을 안정적으로 따릅니다. 작은 모델은 기하급수적으로 성능이 저하되고, 큰 사고 모델은 선형적으로 저하됩니다. Claude Code의 시스템 프롬프트에 이미 ~50개의 지침이 포함되어 있으므로, `CLAUDE.md`는 지침을 최소화해야 합니다 - 이상적으로는 보편적으로 적용 가능한 것만.

### 파일 길이와 적용 가능성

최적의 컨텍스트 윈도우는 집중적이고 관련 있는 정보를 포함합니다. `CLAUDE.md`는 모든 세션에 나타나므로 보편적 적용 가능성을 보장하세요. 관련 없는 작업에서 방해가 되는 작업별 세부사항(예: 데이터베이스 스키마 가이드)을 피하세요.

**권장:** 300줄 미만; 짧을수록 좋습니다. HumanLayer의 루트 파일은 **60줄 미만**입니다.

### Progressive Disclosure (점진적 공개)

작업별 문서를 자체 설명적인 이름으로 별도 유지하세요:

```
agent_docs/
  |- building_the_project.md
  |- running_tests.md
  |- code_conventions.md
  |- service_architecture.md
  |- database_schema.md
  |- service_communication_patterns.md
```

`CLAUDE.md`에는 이 파일들을 간략한 설명과 함께 나열합니다. Claude가 관련성을 판단하고 그에 따라 읽도록 지시하세요.

**복사보다 포인터를 선호하세요.** 시간이 지나면 오래되는 스니펫을 삽입하는 대신 `file:line` 참조를 사용하여 권위 있는 컨텍스트를 가리키세요.

### Claude는 비싼 린터가 아닙니다

린팅을 LLM에 위임하지 마세요 - 결정론적 도구에 비해 비용이 많이 들고 느립니다. 코드 스타일 가이드라인은 컨텍스트 윈도우를 부풀리고 지침 준수를 저하시킵니다.

LLM은 기존 패턴에서 인컨텍스트로 학습합니다. 고려하세요:
- 포매터/린터를 실행하는 Claude Code `Stop` 훅 설정
- 버전 관리 참조가 포함된 가이드라인을 포함하는 슬래시 명령 생성
- Biome 같은 자동 수정 린터 사용

### `/init`을 사용하거나 CLAUDE.md를 자동 생성하지 마세요

자동 생성 도구가 존재하지만 건너뛰세요. `CLAUDE.md`는 모든 워크플로우 단계에 영향을 미치는 하네스의 가장 높은 레버리지 설정 포인트입니다. 자동 생성하는 대신 각 줄을 신중하게 작성하세요.

---

## 결론

1. `CLAUDE.md`는 Claude를 코드베이스에 온보딩하며, **WHY, WHAT, HOW**를 정의합니다
2. 지침을 최소화하세요 - 적고 보편적으로 적용 가능한 것이 더 나은 결과를 만듭니다
3. 내용을 간결하고 광범위하게 관련 있게 유지하세요
4. Progressive Disclosure 사용 - Claude에게 모든 것을 미리 알려주지 말고 정보를 찾는 방법을 알려주세요
5. 린팅은 전용 도구에 위임하고, LLM에 맡기지 마세요
6. 자동 생성을 피하세요; 수동 큐레이션이 더 나은 결과를 만듭니다

## 핵심 요약 테이블

| 원칙 | 설명 |
|------|------|
| **파일 길이** | 300줄 미만 권장, **60줄 미만이 이상적** |
| **포함할 것** | WHAT (기술 스택, 구조), WHY (목적), HOW (워크플로우) |
| **제외할 것** | 코드 스타일 세부 규칙, 작업별 지침, 모든 명령어 나열 |
| **분리 전략** | 작업별 문서는 별도 폴더 (agent_docs/)에 분리 |
| **자동 생성** | /init 사용 금지, 수동으로 신중하게 작성 |
| **린팅** | LLM이 아닌 전용 도구 사용 |
