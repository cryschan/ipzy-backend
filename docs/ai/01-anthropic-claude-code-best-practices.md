# Claude Code: 에이전틱 코딩 베스트 프랙티스

> 출처: https://www.anthropic.com/engineering/claude-code-best-practices
> 작성자: Boris Cherny (Anthropic)

---

## 개요

Claude Code는 Anthropic이 연구 프로젝트로 개발한 에이전틱 코딩을 위한 CLI 도구입니다. 개발자가 Claude를 코딩 워크플로우에 자연스럽게 통합할 수 있도록 하면서, 의도적으로 유연하고 안전한 설계를 유지합니다.

---

## 1. 설정 커스터마이징

### CLAUDE.md 파일 만들기

`CLAUDE.md` 파일은 대화 시작 시 자동으로 컨텍스트에 포함됩니다. 다음 내용을 문서화하는 데 적합합니다:

- 자주 사용하는 bash 명령어
- 핵심 파일과 유틸리티 함수
- 코드 스타일 가이드라인
- 테스트 지침
- 저장소 관례
- 개발 환경 설정
- 프로젝트 특화 경고나 동작

**CLAUDE.md 예시:**
```
# Bash 명령어
- npm run build: 프로젝트 빌드
- npm run typecheck: 타입체커 실행

# 코드 스타일
- ES 모듈 (import/export) 문법 사용
- 가능하면 구조 분해 import 사용

# 워크플로우
- 코드 변경 후 타입체크 실행
- 전체 테스트보다 단일 테스트 선호
```

**파일 위치:**
- 저장소 루트 디렉토리 (권장, git에 커밋)
- 상위 디렉토리 (모노레포에 유용)
- 하위 디렉토리 (필요 시 가져옴)
- 홈 폴더 (`~/.claude/CLAUDE.md`) - 모든 세션에 적용

### CLAUDE.md 파일 튜닝

일반 프롬프트처럼 지속적으로 개선해야 합니다. 효과를 테스트하지 않고 방대한 내용을 추가하지 마세요. `#` 키를 사용하면 Claude가 자동으로 관련 파일에 지침을 통합합니다. Anthropic 팀은 주기적으로 프롬프트 개선기를 돌리고, 준수율을 높이기 위해 "IMPORTANT"나 "YOU MUST" 같은 강조 키워드를 추가합니다.

### 허용 도구 관리

Claude가 사용할 수 있는 도구를 관리하는 4가지 방법:

1. 프롬프트 시 "Always allow" 선택
2. `/permissions` 명령으로 도구 추가/제거
3. `.claude/settings.json` 또는 `~/.claude.json` 수동 편집
4. `--allowedTools` CLI 플래그로 세션별 권한 설정

### GitHub CLI 설치

`gh` CLI를 설치하면 Claude가 GitHub와 더 효과적으로 상호작용할 수 있습니다 (이슈 생성, PR 열기, 코멘트 읽기 등).

## 2. Claude에게 더 많은 도구 제공

### Bash 도구와 함께 사용

Claude Code는 bash 환경을 상속받아 설치된 모든 도구에 접근할 수 있습니다. 커스텀 도구 사용을 돕는 방법:

1. 사용 예시와 함께 도구 이름 제공
2. Claude에게 `--help`를 실행하도록 안내
3. 자주 사용하는 도구를 CLAUDE.md에 문서화

### MCP와 함께 사용

Claude Code는 MCP 서버와 클라이언트 역할을 모두 수행합니다. MCP 서버 연결 방법:

- **프로젝트 설정** (해당 디렉토리에서만 사용 가능)
- **전역 설정** (모든 프로젝트에서 사용 가능)
- **체크인된 .mcp.json** (팀과 공유)

설정 문제 해결 시 `--mcp-debug` 플래그 사용

### 커스텀 슬래시 명령어

`.claude/commands` 폴더에 마크다운 파일로 프롬프트 템플릿을 저장합니다. `/` 메뉴에서 사용 가능하며, `$ARGUMENTS` 키워드로 파라미터를 전달할 수 있습니다.

**예시 명령어** (`.claude/commands/fix-github-issue.md`로 저장):
```
GitHub 이슈를 분석하고 수정해주세요: $ARGUMENTS.

다음 단계를 따르세요:
1. `gh issue view`로 이슈 상세 정보 확인
2. 문제 이해
3. 코드베이스에서 관련 파일 검색
4. 필요한 변경사항 구현
5. 테스트 작성 및 실행
6. 린팅 통과 확인
7. 설명적인 커밋 메시지 작성
8. 푸시 및 PR 생성
```

`/project:fix-github-issue 1234`로 사용하여 이슈 #1234를 수정합니다.

## 3. 일반적인 워크플로우

### 탐색, 계획, 코딩, 커밋

다양한 문제에 적용 가능한 워크플로우:

1. **Claude에게 읽기 요청** - 코드 작성 없이 관련 파일/이미지/URL 읽기
   - 복잡한 탐색에는 서브에이전트 사용 고려
2. **Claude에게 계획 요청** - "think"를 사용하여 확장 사고 모드 활성화
   - "think" < "think hard" < "think harder" < "ultrathink"
   - 계획을 문서나 GitHub 이슈로 저장
3. **Claude에게 구현 요청** - 합리성 검증
4. **Claude에게 커밋 요청** - PR 생성

**1-2단계가 중요합니다** - 이 단계 없이는 Claude가 바로 코딩으로 뛰어듭니다.

### TDD 워크플로우: 테스트 작성, 커밋; 코드, 반복, 커밋

에이전틱 코딩으로 TDD가 더 강력해집니다:

1. Claude에게 입/출력 쌍 기반 테스트 작성 요청 (TDD임을 명시)
2. Claude에게 테스트 실행 및 실패 확인 요청 (구현 작성 금지)
3. Claude에게 테스트 커밋 요청
4. Claude에게 테스트 통과 코드 작성 요청 (테스트 수정 금지)
   - 서브에이전트로 구현이 과적합되지 않았는지 확인
5. Claude에게 코드 커밋 요청

> "Claude는 명확한 목표가 있을 때 최고의 성능을 발휘합니다 - 시각적 목업, 테스트 케이스, 또는 다른 종류의 출력물."

### 코드 작성, 스크린샷, 반복

시각적 목표 제공:

1. Claude에게 스크린샷 찍는 방법 제공 (Puppeteer MCP, iOS 시뮬레이터, 수동 붙여넣기)
2. 시각적 목업 제공 (복사/붙여넣기 또는 이미지 드래그)
3. Claude에게 디자인 구현 및 반복 요청
4. 만족하면 Claude에게 커밋 요청

사람처럼 Claude도 2-3번의 반복으로 출력 품질이 크게 향상됩니다.

### 안전한 YOLO 모드

`claude --dangerously-skip-permissions`로 모든 권한 체크를 우회합니다. 린트 에러 수정이나 보일러플레이트 생성에 적합합니다.

**권장:** 위험을 최소화하기 위해 인터넷 접근이 없는 컨테이너에서만 사용하세요.

### 코드베이스 Q&A

새로운 코드베이스를 학습할 때 Claude Code를 사용하세요:

- 로깅은 어떻게 동작하나요?
- 새 API 엔드포인트는 어떻게 만드나요?
- 이 코드는 무엇을 하나요?
- 이 코드가 처리하는 엣지 케이스는 무엇인가요?
- 왜 이런 접근 방식을 선택했나요?

### Git 작업

Claude는 많은 git 작업을 효과적으로 처리합니다:

- 컨텍스트를 위한 git 히스토리 검색
- 의미 있는 커밋 메시지 작성
- 복잡한 작업 처리 (되돌리기, 리베이스, 충돌 해결)

### GitHub 작업

- PR 생성 (Claude는 "pr" 축약어 이해)
- 코드 리뷰 코멘트 구현
- 실패한 빌드/린터 경고 수정
- 이슈 분류 및 트리아지

## 4. 워크플로우 최적화

### 지침을 구체적으로

> "Claude Code의 성공률은 더 구체적인 지침으로 크게 향상됩니다."

**나쁜 예:** "foo.py에 테스트 추가해줘"
**좋은 예:** "foo.py에 새 테스트 케이스를 작성해줘. 사용자가 로그아웃된 엣지 케이스를 다루고, mock은 피해줘"

**나쁜 예:** "ExecutionFactory의 API가 왜 이상하지?"
**좋은 예:** "ExecutionFactory의 git 히스토리를 살펴보고 API가 어떻게 지금 형태가 되었는지 요약해줘"

### Claude에게 이미지 제공

Claude는 이미지를 잘 처리합니다:
- 스크린샷 붙여넣기 (macOS: cmd+ctrl+shift+4로 클립보드에 복사)
- 이미지 드래그 앤 드롭
- 파일 경로 제공

디자인 목업 기반 UI 개발에 특히 유용합니다.

### 작업할 파일 언급

탭 완성으로 파일/폴더를 참조하면 Claude가 올바른 리소스를 찾거나 업데이트하는 데 도움이 됩니다.

### URL 제공

프롬프트와 함께 URL을 붙여넣으면 Claude가 가져와서 읽습니다. `/permissions`로 도메인을 허용 목록에 추가하세요.

### 조기에 자주 방향 수정

방향 수정에 도움이 되는 4가지 도구:

1. Claude에게 먼저 계획을 세우도록 요청 (확인 전까지 코딩 금지)
2. Escape를 눌러 컨텍스트를 잃지 않고 중단
3. Escape 두 번 눌러 히스토리로 돌아가 프롬프트 수정, 다른 방향 탐색
4. Claude에게 변경사항 되돌리기 요청

### `/clear`로 컨텍스트 집중 유지

작업 간에 `/clear`를 자주 사용하여 컨텍스트 윈도우를 리셋하고 성능을 향상시키세요.

### 체크리스트와 스크래치패드 사용

여러 단계의 대규모 작업에서는 마크다운 파일이나 GitHub 이슈를 체크리스트로 사용하여 성능을 향상시키세요:

1. 린트 명령 실행 후 모든 에러를 마크다운 체크리스트에 작성
2. 하나씩 문제 해결, 검증, 체크오프

### Claude에 데이터 전달

여러 방법이 있습니다:

- 프롬프트에 직접 복사/붙여넣기 (가장 일반적)
- Claude Code로 파이프 (예: `cat foo.txt | claude`)
- bash/MCP 도구/커스텀 명령으로 데이터 가져오기
- Claude에게 파일 읽기 또는 URL 가져오기 요청

## 5. 헤드리스 모드로 인프라 자동화

Claude Code는 CI, pre-commit 훅, 빌드 스크립트 같은 비대화형 컨텍스트를 위한 헤드리스 모드를 포함합니다. `-p` 플래그와 프롬프트, `--output-format stream-json`으로 스트리밍 출력을 사용합니다.

### 이슈 트리아지에 Claude 사용

헤드리스 모드는 GitHub 이벤트로 트리거되는 자동화를 지원합니다. 공개 Claude Code 저장소는 Claude를 사용하여 새 이슈를 검사하고 적절한 라벨을 할당합니다.

### 린터로서의 Claude

> "Claude Code는 전통적인 린팅을 넘어서는 주관적인 코드 리뷰를 제공합니다" - 오타, 오래된 주석, 오해의 소지가 있는 이름을 식별합니다.

## 6. 멀티 Claude 워크플로우로 레벨업

### 하나의 Claude가 코드 작성; 다른 Claude가 검증

분리된 컨텍스트가 더 나은 결과를 만들어냅니다:

1. Claude로 코드 작성
2. `/clear` 실행 또는 두 번째 Claude 시작
3. 두 번째 Claude가 작업 리뷰
4. 피드백 기반으로 편집할 다른 Claude 시작

### 저장소 여러 체크아웃 사용

순차적 완료를 기다리지 않고:

1. 별도 폴더에 3-4개의 git 체크아웃 생성
2. 각각을 별도 터미널 탭에서 열기
3. 각각에서 다른 작업으로 Claude 시작
4. 진행 상황을 순환하며 확인

### Git Worktree 사용

독립적인 작업을 위한 여러 체크아웃의 경량 대안:

1. worktree 생성: `git worktree add ../project-feature-a feature-a`
2. 각각에서 Claude 시작: `cd ../project-feature-a && claude`
3. 필요에 따라 추가 worktree 생성
4. 정리: `git worktree remove ../project-feature-a`

**팁:**
- 일관된 명명 규칙 사용
- worktree당 하나의 터미널 탭 유지
- 알림 설정 (Mac에서 iTerm2)
- 다른 worktree에 별도 IDE 창 사용

### 커스텀 하네스로 헤드리스 모드 사용

두 가지 주요 패턴:

1. **팬아웃** - 대규모 마이그레이션/분석:
   - Claude에게 작업 목록 스크립트 작성 요청
   - 작업을 순회하며 Claude를 프로그래밍 방식으로 호출
   - 프롬프트를 반복적으로 개선

2. **파이프라이닝** - 데이터/처리 파이프라인:
   - `claude -p "<prompt>" --json | your_command` 호출
   - 디버깅에 `--verbose` 플래그 사용
