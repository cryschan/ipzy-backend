## 1. 네트워크란?

**컴퓨터들이 데이터를 주고받는 통신망**

```
┌──────────┐                      ┌──────────┐
│ 클라이언트 │ ◀──── 네트워크 ────▶ │   서버    │
│ (브라우저) │                      │ (Spring) │
└──────────┘                      └──────────┘
```

## 2. OSI 7계층

네트워크 통신을 7단계로 나눈 표준 모델

```
┌─────────────────────────────────────────────────────────────┐
│  7. 응용 계층 (Application)    │ HTTP, DNS    │ 웹, API     │
├─────────────────────────────────────────────────────────────┤
│  6. 표현 계층 (Presentation)   │ SSL, JSON    │ 암호화, 변환 │
├─────────────────────────────────────────────────────────────┤
│  5. 세션 계층 (Session)        │ -            │ 연결 유지    │
├─────────────────────────────────────────────────────────────┤
│  4. 전송 계층 (Transport)      │ TCP, UDP     │ 포트, 신뢰성 │
├─────────────────────────────────────────────────────────────┤
│  3. 네트워크 계층 (Network)     │ IP, 라우터   │ 경로 선택    │
├─────────────────────────────────────────────────────────────┤
│  2. 데이터링크 계층 (Data Link) │ MAC, 스위치  │ 로컬 전달    │
├─────────────────────────────────────────────────────────────┤
│  1. 물리 계층 (Physical)       │ 케이블, 신호  │ 물리적 전송  │
└─────────────────────────────────────────────────────────────┘
```

### 왜 계층을 나눌까?

```
문제: "인터넷이 안 돼요"

계층이 없다면 → 어디가 문제인지 모름
계층이 있다면 → 어느 계층 문제인지 좁혀갈 수 있음

- 케이블 뽑혔나? (1계층)
- IP 설정 잘못됐나? (3계층)
- 서버가 응답 안 하나? (7계층)
```

### 데이터 전송 흐름 (캡슐화)

```
보내는 쪽                          받는 쪽
─────────                          ─────────
     데이터                              데이터
       ↓ 7계층                      7계층 ↑
   [HTTP 헤더 + 데이터]          [HTTP 헤더 + 데이터]
       ↓ 4계층                      4계층 ↑
  [TCP 헤더 + ...]              [TCP 헤더 + ...]
       ↓ 3계층                      3계층 ↑
  [IP 헤더 + ...]               [IP 헤더 + ...]
       ↓ 2계층                      2계층 ↑
 [MAC 헤더 + ...]              [MAC 헤더 + ...]
       ↓ 1계층                      1계층 ↑
    전기 신호  ───────────────▶  전기 신호
```

## 3. 각 계층 상세

### 3.1 물리 계층 (1계층)

**역할**: 0과 1을 전기/광 신호로 변환

```
디지털 데이터: 01001000 01101001
                  ↓
전기 신호:    ⎍⎍__⎍___⎍⎍___⎍__⎍
```

| 구성 요소 | 예시 |
|-----------|------|
| 전송 매체 | 이더넷 케이블, 광케이블, 와이파이 |
| 장비 | 허브, 리피터 |
| 단위 | 비트 (bit) |

### 3.2 데이터링크 계층 (2계층)

**역할**: 같은 네트워크 내 장치 간 통신 (MAC 주소 사용)

```
┌─────────────────────────────────────┐
│            같은 공유기 내            │
│  PC1 ◀────── 스위치 ──────▶ PC2    │
│  MAC: AA           MAC: CC         │
└─────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| MAC 주소 | 장치 고유 주소 (AA:BB:CC:DD:EE:FF) |
| 프레임 | 이 계층의 데이터 단위 |
| 장비 | 스위치, 브릿지 |

### 3.3 네트워크 계층 (3계층)

**역할**: 다른 네트워크 간 통신 (IP 주소, 경로 선택)

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│ 네트워크 A │ ──────▶│  라우터   │──────▶ │ 네트워크 B │
│192.168.1.x│         │          │         │10.0.0.x  │
└──────────┘         └──────────┘         └──────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| IP 주소 | 논리적 주소 (설정 가능) |
| 패킷 | 이 계층의 데이터 단위 |
| 장비 | 라우터 |

### 3.4 전송 계층 (4계층)

**역할**: 신뢰성 있는 데이터 전송, 포트 번호로 프로세스 구분

```
┌─────────────────────────────────┐
│          서버 (10.0.0.5)         │
│  ┌──────┐  ┌──────┐  ┌──────┐  │
│  │:80   │  │:443  │  │:8080 │  │
│  │ Web  │  │HTTPS │  │ API  │  │
└─────────────────────────────────┘
```

| 프로토콜 | 특징 | 용도 |
|----------|------|------|
| TCP | 신뢰성, 순서 보장, 느림 | 웹, 이메일 |
| UDP | 빠름, 신뢰성 X | 게임, 스트리밍 |

### 3.5 응용 계층 (7계층)

**역할**: 사용자와 가장 가까운 계층, 애플리케이션 서비스 제공

| 프로토콜 | 용도 |
|----------|------|
| HTTP/HTTPS | 웹 |
| FTP | 파일 전송 |
| SMTP | 이메일 발송 |
| DNS | 도메인 → IP 변환 |
| SSH | 원격 접속 |

## 4. 핵심 개념 상세

### 4.1 MAC 주소

**네트워크 장치의 고유 식별 번호** - 공장에서 새겨진 하드웨어 주소

```
AA:BB:CC:DD:EE:FF
──────── ────────
  제조사    일련번호
```

```bash
# 확인 방법
ifconfig | grep ether  # Mac
ipconfig /all          # Windows
```

#### IP vs MAC 비교

| 구분 | MAC 주소 | IP 주소 |
|------|----------|---------|
| 비유 | 주민등록번호 | 집 주소 |
| 변경 | 불가 (고정) | 가능 (유동) |
| 할당 | 제조사가 공장에서 | 네트워크 관리자/DHCP |
| 범위 | 로컬 네트워크 내 | 전 세계 |
| 계층 | 2계층 | 3계층 |

### 4.2 스위치 vs 라우터

| 구분 | 스위치 | 라우터 |
|------|--------|--------|
| 계층 | 2계층 | 3계층 |
| 주소 | MAC 주소 | IP 주소 |
| 범위 | 같은 네트워크(LAN) | 다른 네트워크 간 |
| 비유 | 아파트 경비원 | 택배 물류센터 |

```
스위치 = 같은 동네 안에서 배달
라우터 = 다른 도시로 가는 길 안내
```

### 4.3 TCP vs UDP

| 구분 | TCP | UDP |
|------|-----|-----|
| 비유 | 등기 우편 | 전단지 뿌리기 |
| 연결 | 연결 후 전송 | 그냥 보냄 |
| 신뢰성 | 도착 확인, 재전송 | 확인 안 함 |
| 순서 | 보장 | 보장 안 함 |
| 속도 | 느림 | 빠름 |

#### TCP 동작

```
보내는 쪽                      받는 쪽
    │                            │
    │ ─── 1번 패킷 ───────────▶ │
    │ ◀── "1번 받았어" ──────── │ (ACK)
    │                            │
    │ ─── 2번 패킷 ───────────▶ │
    │ ◀── "2번 받았어" ──────── │ (ACK)
```

#### UDP 동작

```
보내는 쪽                      받는 쪽
    │                            │
    │ ─── 1번 패킷 ───────────▶ │
    │ ─── 2번 패킷 ───────────▶ │
    │ ─── 3번 패킷 ─────X       │  ← 손실되면 끝
    │   (확인 안 함)             │
```

#### 사용 예시

| 서비스 | 프로토콜 | 이유 |
|--------|----------|------|
| 웹 (HTTP) | TCP | 페이지 깨지면 안 됨 |
| 파일 다운로드 | TCP | 파일 손상 방지 |
| 온라인 게임 | UDP | 1ms라도 빨라야 함 |
| 유튜브 스트리밍 | UDP | 끊김 > 버퍼링 |

### 4.4 포트 번호

**TCP/UDP가 관리, 프로그램 구분**

```
192.168.0.1:8080
─────────── ────
    IP      포트

IP = 건물 주소
포트 = 건물 안의 호수
```

| 포트 | 용도 |
|------|------|
| 80 | HTTP |
| 443 | HTTPS |
| 22 | SSH |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 8080 | 개발 서버 (관례) |

## 5. HTTP 프로토콜

### 요청 구조

```
GET /api/users/1 HTTP/1.1        ← 요청 라인
Host: localhost:8080             ← 헤더 시작
Authorization: Bearer eyJhbG...
Content-Type: application/json
                                 ← 빈 줄 (헤더 끝)
{"name": "홍길동"}                ← 바디 (POST/PUT 시)
```

### 응답 구조

```
HTTP/1.1 200 OK                  ← 상태 라인
Content-Type: application/json
                                 ← 빈 줄
{"id": 1, "name": "홍길동"}       ← 바디
```

### HTTP 메서드

| 메서드 | 용도 | 특징 |
|--------|------|------|
| GET | 조회 | 바디 없음 |
| POST | 생성 | 바디 있음 |
| PUT | 전체 수정 | 바디 있음 |
| PATCH | 부분 수정 | 바디 있음 |
| DELETE | 삭제 | 바디 없음 |

### 상태 코드

| 코드 | 의미 | 예시 |
|------|------|------|
| 2xx | 성공 | 200 OK, 201 Created |
| 3xx | 리다이렉트 | 301 Moved, 302 Found |
| 4xx | 클라이언트 오류 | 400 Bad Request, 404 Not Found |
| 5xx | 서버 오류 | 500 Internal Server Error |

## 6. 실제 통신 예시

### 웹 요청 흐름

```
1. 사용자: 브라우저에 "ipzy.com/api/users" 입력

2. DNS 조회
   ipzy.com → 13.125.xxx.xxx (IP 획득)

3. TCP 연결 (3-Way Handshake)
   클라이언트 ↔ 서버 연결 수립

4. HTTP 요청 전송
   GET /api/users HTTP/1.1
   Host: ipzy.com

5. 서버 처리
   Tomcat → Filter → DispatcherServlet → Controller → ...

6. HTTP 응답 반환
   HTTP/1.1 200 OK
   {"users": [...]}

7. TCP 연결 종료 (또는 Keep-Alive로 유지)
```

### 경로 추적

```bash
# 어떤 라우터들을 거치는지 확인
traceroute google.com

1  192.168.0.1      ← 집 공유기
2  121.xxx.xxx.1    ← ISP 라우터
3  ...
10 142.250.196.100  ← Google 서버
```

## 7. 핵심 요약

### 기억해야 할 5개 계층

```
7계층: HTTP     → "무슨 내용?"
4계층: TCP/UDP  → "어느 포트? 신뢰성?"
3계층: IP       → "어디로?"
2계층: MAC      → "바로 옆 누구한테?"
1계층: 케이블   → "물리적으로 전송"
```

### 주소 비교

```
MAC = "이 기계가 누구인가" (신원) - 변경 불가
IP  = "이 기계가 어디 있는가" (위치) - 변경 가능
포트 = "어느 프로그램인가" (호수)
```

### 장비 비교

```
허브    = 1계층, 신호 복제 (멍청)
스위치  = 2계층, MAC 주소로 전달
라우터  = 3계층, IP 주소로 경로 선택
```

## 8. 참고 명령어

```bash
# MAC 주소 확인
ifconfig | grep ether

# IP 설정 확인
ifconfig

# 라우팅 테이블
netstat -rn

# ARP 테이블 (IP-MAC 매핑)
arp -a

# 경로 추적
traceroute google.com

# 연결 테스트
ping google.com

# 포트 연결 테스트
telnet google.com 443
```
