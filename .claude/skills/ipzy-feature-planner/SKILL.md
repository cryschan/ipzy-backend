# IPZY Feature Planner

새로운 기능 구현 전 영향 분석, 구현 순서, 테스트 계획, 롤백 전략을 종합적으로 수립합니다.

## 사용 시점

- 3개 이상 파일 변경이 예상될 때
- 다중 도메인에 영향을 줄 때
- 외부 API 연동이 필요할 때
- DB 스키마 변경이 필요할 때
- 보안/결제 관련 기능일 때

## 워크플로우

```
기능 요청
       ↓
[1단계] 영향 분석
       ↓
[2단계] 기술 검토
       ↓
[3단계] 구현 계획
       ↓
[4단계] 테스트 계획
       ↓
[5단계] 롤백 계획
       ↓
계획서 출력 → 승인 후 구현
```

## 사용 예시

### 입력
```
"결제 기능 구현해줘"
```

### 출력 (요약)
```markdown
# 결제 기능 구현 계획서

## 1. 기능 개요
토스페이먼츠 연동을 통한 구독 결제 기능

## 2. 영향 분석
- payment 도메인 (신규)
- subscription 도메인 (연동)
- user 도메인 (결제 정보 연결)

## 3. 기술 검토
- 토스페이먼츠 API 연동
- 웹훅 처리 필요
- 결제 상태 관리

## 4. 구현 계획
Phase 1: Payment 엔티티 및 기본 구조
Phase 2: 토스페이먼츠 연동
Phase 3: 웹훅 처리
Phase 4: 구독 연동

## 5. 테스트 계획
- 샌드박스 환경 테스트
- 결제 실패 케이스 테스트
- 동시성 테스트

## 6. 롤백 계획
- Feature flag로 기능 비활성화
- 결제 데이터 보존 (삭제 X)

위 계획으로 진행할까요?
```

## 복잡도 판단 기준

| 복잡도 | 기준 |
|--------|------|
| 낮음 | 단일 도메인, 외부 연동 없음 |
| 중간 | 2-3개 도메인, 간단한 외부 연동 |
| 높음 | 다중 도메인, 결제/보안, DB 스키마 변경 |

## 트리거 키워드

- "계획 세워줘", "플랜 만들어줘"
- "어떻게 구현할지", "구현 방법"
- 복잡한 기능 요청 시 자동 제안
