# IPZY Refactor Guide

코드 리팩토링 계획을 수립하고 안전한 리팩토링 절차를 안내합니다.

## 리팩토링 원칙

1. **테스트 먼저**: 기존 테스트 통과 확인 후 시작
2. **작은 단위**: 한 번에 하나의 변경만
3. **자주 검증**: 변경 후 즉시 테스트
4. **롤백 가능**: 언제든 되돌릴 수 있게

## 워크플로우

```
리팩토링 대상 분석
       ↓
[1단계] 문제점 식별
       ↓
[2단계] 리팩토링 전략 수립
       ↓
[3단계] 영향 범위 분석
       ↓
[4단계] 단계별 실행 계획
       ↓
[5단계] 검증 계획
       ↓
리팩토링 가이드 출력
```

## 4. 단계별 실행 계획

### Phase 1: 준비

```
1.1 기존 테스트 실행 및 통과 확인
    ./gradlew test --tests "{TargetClass}Test"

1.2 테스트 커버리지 확인
    - 커버리지 부족 시 테스트 추가

1.3 git 브랜치 생성
    git checkout -b refactor/{target-name}
```

### Phase 2: 리팩토링 실행

#### Step 1: {첫 번째 변경}

```java
// 변경 내용
{코드 변경}
```

**검증:**
```bash
./gradlew test
```

#### Step 2: {두 번째 변경}

```java
// 변경 내용
{코드 변경}
```

**검증:**
```bash
./gradlew test
```

#### Step 3: {세 번째 변경}

...

### Phase 3: 정리

```
3.1 사용하지 않는 import 제거
3.2 코드 포맷팅
    ./gradlew spotlessApply

3.3 전체 테스트 실행
    ./gradlew clean test

3.4 빌드 확인
    ./gradlew build
```

## 5. 검증 계획

### 5.1 단계별 검증

| 단계 | 검증 방법 | 통과 기준 |
|------|-----------|-----------|
| Step 1 | 단위 테스트 | 기존 테스트 통과 |
| Step 2 | 단위 테스트 | 기존 테스트 통과 |
| 완료 | 전체 테스트 | 모든 테스트 통과 |

### 5.2 회귀 테스트

```bash

./gradlew test --tests "com.ipzy.domain.{domain}.*"

# 통합 테스트
./gradlew test --tests "*IntegrationTest"
```

| 로그 | 에러 로그 없음 | [ ] |

## 리팩토링 기법 참조

### 클래스 분리 (Extract Class)

**적용 시점:**
- 클래스가 200줄 이상
- 두 가지 이상의 책임

**절차:**
1. 분리할 책임 식별
2. 새 클래스 생성
3. 필드/메서드 이동
4. 기존 클래스에서 위임

### 메서드 추출 (Extract Method)

**적용 시점:**
- 메서드가 20줄 이상
- 주석으로 설명이 필요한 코드 블록

**절차:**
1. 추출할 코드 블록 식별
2. 새 메서드 생성
3. 코드 이동
4. 기존 위치에서 호출

### 서비스 분리

**적용 시점:**
- Service가 10개 이상 메서드
- 서로 다른 도메인 로직 혼재

**절차:**
1. 책임별 그룹화
2. 새 Service 클래스 생성
3. 메서드 이동
4. Controller 의존성 변경

## 사용 예시

### 입력
```
"UserService 리팩토링해줘"
```

### 출력 (요약)
```markdown
# UserService 리팩토링 가이드

## 현재 상태
- 라인 수: 350 (권장 200 이하)
- 메서드 수: 18개 (권장 15 이하)
- 책임: 인증, 프로필, 설정 혼재

## 문제점
- Large Class: 너무 많은 책임
- 관련 없는 메서드들이 한 클래스에

## 리팩토링 전략
1. UserProfileService 분리
2. UserSettingsService 분리
3. UserService는 조회만 담당

## 목표 구조
UserService (조회)
UserProfileService (프로필 관리)
UserSettingsService (설정 관리)

## 실행 계획
Step 1: UserProfileService 생성
Step 2: 프로필 메서드 이동
Step 3: UserSettingsService 생성
Step 4: 설정 메서드 이동
Step 5: Controller 의존성 변경
```
