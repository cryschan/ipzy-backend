# IPZY Changelog

코드 변경사항을 자동으로 문서화하여 `docs/changelog/` 폴더에 기록합니다.

## 필수 실행 사항

이 스킬이 호출되면 **반드시 다음을 실행**합니다:

1. `git diff HEAD --name-status`로 변경 파일 수집
2. `git diff HEAD --stat`로 변경 라인 수 확인
3. `docs/changelog/` 폴더가 없으면 생성
4. `docs/changelog/YYYYMMDD_HHMMSS.md` 파일 **실제 생성** (Write 도구 사용)
5. `docs/changelog/README.md` 인덱스 **실제 갱신** (Write 도구 사용)

**중요: 템플릿만 보여주지 말고, 실제 파일을 생성하세요!**

## 워크플로우

```
코드 변경 완료
       ↓
[1단계] 변경사항 수집 (git diff) - Bash 실행
       ↓
[2단계] 변경 분석 및 분류
       ↓
[3단계] 문서 생성 - Write 도구로 파일 생성
       ↓
[4단계] 인덱스 갱신 - Write 도구로 README.md 갱신
       ↓
docs/changelog/YYYYMMDD_HHMMSS.md 생성 완료
```

## 1단계: 변경사항 수집

### Git 명령어
```bash
# staged + unstaged 변경사항
git diff HEAD --name-status

# 변경된 라인 수
git diff HEAD --stat

# 상세 diff
git diff HEAD
```

### 수집 정보
- 변경된 파일 목록
- 각 파일의 변경 유형 (A: 추가, M: 수정, D: 삭제)
- 변경된 라인 수 (+/-)

## 2단계: 변경 분석

### 변경 유형 분류
| 유형 | 판단 기준 |
|------|-----------|
| 새 기능 | 새 파일 추가, 새 메서드 추가 |
| 버그 수정 | 기존 로직 수정, 조건문 변경 |
| 리팩토링 | 구조 변경, 이름 변경, 파일 이동 |
| 문서화 | Swagger 어노테이션, 주석 추가 |
| 테스트 | 테스트 파일 추가/수정 |
| 설정 | application.yml, build.gradle 변경 |
